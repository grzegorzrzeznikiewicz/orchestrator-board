# OB-11: pull request CI implementation plan

> Execute inline using superpowers:executing-plans. Keep all changes uncommitted.

**Goal:** Require static analysis, tests, secret scanning and generated-contract checks through one `CI / required` result, with desktop packaging kept separate.

**Architecture:** An always-triggered CI workflow selects affected areas and calls the existing test workflows. A final job validates every required result, including the selector itself. Unknown paths trigger all checks rather than silently omitting coverage.

**Tech stack:** GitHub Actions, Node.js 24, Go from go.mod, ESLint 10, typescript-eslint, React Hooks, actionlint.

**Spec:** [OB-11](https://gamasoftware.atlassian.net/browse/OB-11) and the approved design in this conversation.

## Constraints

- Work in the actual project directory on `feature/OB-11`, based on `origin/main`.
- Initial implementation stayed uncommitted and unpushed. On 2026-10-16 the user authorized commit, push, a PR and merge after successful pipeline verification. No additional worktrees or releases.
- Preserve the existing backend race-test shards, CLI OS matrix and Windows regression checks.
- Required workflow must run on every PR to main, including documentation changes.
- Existing frontend lint debt may use an explicit, reviewable ESLint suppression baseline; CI never regenerates it.
- Remote execution and branch rules cannot be validated or enabled safely before the user authorizes pushing this change. Document the activation steps.

## Review focus

1. Missing selector output, failed or cancelled jobs must never produce a green gate.
2. Docs-only changes must finish without waiting for filtered-out workflows.
3. Workflow, lockfile, contract and shared-package changes must select their dependents.
4. First pushes, deleted and renamed paths must retain coverage; unknown paths select everything.
5. ESLint must reject new violations while leaving existing application behavior unchanged.
